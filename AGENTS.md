# AGENTS.md

Как вести работу в этом репозитории. Правила общие для людей и для агентов.

## Коммитить по мере работы, а не в конце

Каждая законченная правка сразу становится коммитом. Копить изменения в рабочем дереве
«до конца задачи» нельзя: задача может затянуться, а правка уже готова и проверена.

- **Один коммит — одна причина измениться.** Фича, исправление, рефакторинг, документы,
  CI — разные коммиты. Если хочется написать в сообщении «и ещё», это два коммита.
- **Порядок:** сделал → проверил (`npm run typecheck` или `npm run build`) → `git status`,
  чтобы в коммит не попал мусор (`dist/`, `.tmp/`, снимки) → `git add` конкретных файлов →
  коммит → следующая правка.
- **Коммитится работающее.** После каждого коммита сборка проходит; лучше маленькая
  законченная правка, чем большой полуготовый кусок.
- **Правка не удалась — откат, а не коммит «как есть».** `git checkout -- <файл>` дешевле,
  чем потом разбирать историю.
- **Форматирование и переименования — отдельно** от смысловых изменений, иначе дифф
  нечитаем, а `git blame` бесполезен.
- **Сообщения** — Conventional Commits, английский, нижний регистр, императив:
  `feat(world):`, `fix(controller):`, `docs:`, `chore:`, `ci:`. Заголовок до ~72 знаков;
  тело — только если нужно объяснить «почему», а не «что».
- **CHANGELOG.md** обновляется тем же коммитом, что и заметная для игрока правка
  (раздел `[Не выпущено]`), а не отдельным «догоняющим» коммитом.
